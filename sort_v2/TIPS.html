1 总览：算子在 B200 上活下来的三层

① 能编过 · Build

评测镜像的工具链 ≠ 你本机。PyTorch JIT extension、C++ 标准、arch flag 任何一个不对，连 kernel 都启动不了。

② 算得对 · Correctness

float 符号位、稳定排序、不破坏 input、边界 n=0、末 block 的 shfl 全员参与……正确性是性能优化的门票。

③ 跑得快 · Performance

B200 带宽巨大，sort 常是 memory-bound。先保证 histogram / scan / scatter 结构正确，再谈 TMA、onesweep、CUB。

核心结论

这次 sort_v2 的「胜利条件」首先是评测机能编译并给出正确结果。fancy API（TMA experimental）在工具链不匹配时反而全盘皆输。

🎬 B200 心智模型（示意）
HBM3e · 超高带宽 · sort 多为 memory-bound
绿色扫描线 ≈ SM 在吐吞吐；紫色条 ≈ HBM 流量

2 踩坑时间线（真实路径）

❌ v1 · TMA + load_inline + sm_90a

Hopper 味道的 TMA（boxDim>256、SWIZZLE_128B、barrier init=1、缺 expect_tx），再叠加错误 arch。正确性与可编译性双杀。

❌ v2 · 修 TMA 约束后仍 load_inline

CUDA 13.3 上 experimental TMA API 弃用警告；更致命的是 torch 头文件被带进 .cu，触发 List_inl.h 编译错误。

❌ v3 · 改 CUB + load_inline

内核换成 CUB 仍失败——说明锅在 load_inline 的 nvcc 命令行（torch isystem + c++17），不在排序算法本身。

✅ v4 · standalone nvcc → .so + ctypes

彻底不让 torch 参与 CUDA 编译。手写 8-bit radix，scratch ping-pong 不破坏 input，sm_100。评测通过。

💡 TIP · 分层排错 先问「能不能编过」，再问「结果对不对」，最后才问「够不够快」。把编译问题当成算法问题，会浪费整晚。

3 编译与部署：B200 评测机生存指南

💣 雷区 · load_inline

  • main.cpp：-std=c++20 ✅
  • cuda.cu：-std=c++17 + torch -isystem ❌
  • 触发 ATen List_inl.h dependent-scope error
  • 与你写不写 TMA / CUB 无关
→

🛡️ 安全区 · standalone

  • nvcc -shared -Xcompiler -fPIC
  • 零 torch headers
  • -gencode=arch=compute_100,code=sm_100
  • Python ctypes.CDLL 调 extern "C"

推荐构建骨架（与 submission.py 一致）

# 1) 写出纯 CUDA 源（无 torch）
# 2) 编译共享库
nvcc -shared -Xcompiler -fPIC -O3 -std=c++17 \
  -gencode=arch=compute_100,code=sm_100 \
  -gencode=arch=compute_100,code=compute_100 \
  sort.cu -o libsort.so

# 3) Python 侧
lib = ctypes.CDLL("libsort.so")
lib.launch_sort_f32.argtypes = [c_void_p, c_void_p, c_int]
lib.launch_sort_f32(c_void_p(x.data_ptr()), c_void_p(y.data_ptr()), n)
torch.cuda.synchronize()  # 正确性检查前记得 sync

数据流：不破坏 input 的 ping-pong

// Pass 0:  input  → output
// Pass 1:  output → scratch
// Pass 2:  scratch → output
// Pass 3:  output → scratch
// 若最终结果在 scratch，再 D2D copy 到 output
const T *in = d_input;
T *out = d_output;
for (pass ...) {
  hist / scan / scatter(in → out);
  in = out;
  out = (out == d_output) ? d_scratch : d_output;
}
✅ 为什么必须 scratch？ 若用 input 当第二缓冲，会原地改写调用方 tensor。 x.contiguous() 在已连续时不会拷贝，直接把用户数据当 scratch——正确性测试可能仍过，但接口契约坏了。

Histogram

每 block 256 线程，shared 上 256-bin 局部直方图，再写到 block_hist[block][bucket]。避免全局 atomic 热点。

Block Scan

256 线程（一线程一 bucket）串行扫所有 block，得到 exclusive base。正确但 O(num_blocks)——大 N 时是优化点。

Prefix (256)

warp Kogge-Stone + 单 warp 归约，算各 bucket 的全局起始偏移。小到可以单 block 完成。

Scatter

稳定写：global_off + block_base + warp_off + lane_rank。随机写 HBM，通常是整趟 sort 的瓶颈之一。

5 Float → 无符号序：符号位翻转（动画）

IEEE 754 不能直接当无符号整数比大小。经典手法： mask = (bits >> 31) | 0x80000000，再 bits ^ mask。 负数整体翻转到低半区，正数保留符号位为 1 的高半区，从而 radix 按无符号桶排序即数值序。

点击开始

高 8 位高亮 = 当前 pass 的 bucket（shift=24 时示意） 

// float32 get_bucket
uint32_t bits = __float_as_uint(val);
uint32_t mask = (int32_t(bits) >> 31) | 0x80000000u;
return ((bits ^ mask) >> shift) & 0xFF;
⚠️ 特殊值 -0.0 / +0.0、NaN 的 bit 序与 torch.sort 未必完全一致。 若 harness 含 NaN，需对照参考实现；普通有限值这套变换是标准且可靠的。

6 稳定 Scatter：rank 动画

同一 bucket 内要保持输入相对序（stable）。submission 用三层偏移： 

out_index = d_offsets[bucket]          // 全局 bucket 起点
          + d_block_base[block][bucket]  // 本 block 之前的同 bucket 数
          + warp_offs[warp][bucket]      // 本 block 内前序 warp
          + rank;                        // 同 warp 内 lane 序
8 个元素 · 按 bucket 着色写入

同色 = 同 bucket。写入顺序从左到右模拟「先出现的先占坑」——稳定排序的视觉版。

🚫 shfl 陷阱 __shfl_sync(0xffffffff, ...) 要求 mask 内所有 lane 都执行。 不要把 shfl 塞进 if (gid < n)——末 block 会有活 lane 永远等死 lane，直接 hang。

7 TMA 为什么这次没上？（避雷清单）

Hopper/Blackwell 的 TMA 很香，但 API 约束极严。sort_v2 早期 TMA 版踩过的坑：

  • ×
    boxDim ≤ 256
    一次 TMA tile 每维最多 256 元素。2048 直接 Encode 失败。
  • ×
    线性 smem 必须 SWIZZLE_NONE
    SWIZZLE_128B 会重排 bank；你还按 smem[i] 读 = 数据错乱。
  • ×
    barrier 期望 arrive 数 = 参与线程数
    init(&bar, 1) 却 256 线程 arrive_and_wait = UB / hang。
  • ×
    必须 barrier_expect_tx(bytes)
    TMA 用 complete_tx 减计数；不 expect 就等不到完成。
  • ×
    CUDA 13.3 experimental API 弃用
    应迁到 cuda::ptx::cp_async_bulk_tensor，并在匹配的工具链上验证。
  • ✓
    正确性优先时：普通 load + 清晰 radix
    先过测再上 TMA。带宽优化建立在「编得过、结果对」之上。

9 下一步：怎么冲 Leaderboard

当前实现是「正确基线」。要进榜通常还要：

算法层

  • 分层 / CUB 做 block scan，干掉 O(grid) 串行
  • Onesweep / 减少 pass 间全局同步
  • 直接链 CUB DeviceRadixSort（注意编译隔离）
  • digit size 调参（7/8 bit）权衡 hist 与 pass 数

体系结构层

  • 在独立 nvcc 工程里试 TMA load（box≤256, NONE swizzle）
  • scatter 侧减少 bank 冲突 / 多通道缓冲
  • 持久化缓冲，避免每 shape 都 cudaMalloc
  • Nsight Compute 看 memory throughput 与 warp stall
💡 方法论 每一次优化只动一个变量，并在 B200 评测机上回归正确性。 「本地 3050 快 10%」对 leaderboard 几乎无信息量。
